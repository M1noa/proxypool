endpoint

GET https://proxies.minoa.cat/list

only GET and HEAD. anything else returns 405. data comes from the proxypool output branch, which a github action refreshes hourly.

bare /list with no query string returns the upstream proxies.json byte for byte, as application/json. add any param and the request goes through the filter pipeline instead, defaulting to format=txt.

responses are cached 30 seconds at the edge, keyed on the normalized filter set, so ?type=http&format=json and ?format=json&type=HTTP hit the same entry. sort=random is never cached.

no auth, no rate limit, no cost. please don't hammer it in a loop when the data only changes once an hour.

extra params stack on top of a shortcut: /socks5.txt?country=us&limit=50. if the same filter shows up in both the path and the query string, the path wins. a shortcut shares its cache entry with the long /list?… form, so both return identical bytes.

unknown is ambiguous in the data, since both anonymity and ip_type have an empty value. /unknown.ext means anonymity. for the other one, write it out: /list?ip_type=unknown.

params

multi-value params accept repetition (?type=http&type=socks5), commas (?type=http,socks5), or a mix. values are case-insensitive. any or all clears a filter. an unrecognized param name or value returns 400 instead of being ignored.

the txt rule

with exactly one type selected, lines are bare ip:port, because the protocol is already known from your request. with zero or two or more types, lines carry the scheme and a proxy speaking several protocols gets one line each.

errors

errors render in the format you asked for, so a script parsing json keeps parsing json when something goes wrong.

statuscodewhen
400bad_requestunknown param, invalid value, impossible range
404plain textpath isn't /list or a shortcut
405method_not_allowedanything other than GET or HEAD
500internal_errorbug on our side
502upstream_unreachable, upstream_error, upstream_bad_json, upstream_bad_shapegithub raw is down or serving garbage

/list?format=json&limit=huge

{
  "error": {
    "status": 400,
    "code": "bad_request",
    "message": "invalid limit \"huge\" — must be an integer"
  }
}

txt gives error 400 (bad_request): …, jsonl gives the same object on one line, csv gives an error,message header plus one row.

examples

  • /list everything, raw upstream json
  • /socks5.txt socks5 as ip:port lines
  • /elite.json?country=de&limit=50 50 fastest elite proxies in germany
  • /list?type=socks4&type=socks5&format=txt both socks versions, scheme prefixed
  • /list?type=http&min_reliability=0.9&response_max=1000&format=csv reliable and quick, as csv
  • /isp.jsonl?https=true&sort=quality residential isp ips that tunnel tls, best first
  • /list?sort=random&limit=1&format=txt one at random, never cached
